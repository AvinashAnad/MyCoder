type: prompt

When explaining code:
1. Read the file first.
2. Start with a one-sentence summary of what it does.
3. Walk through the key logic — what happens and why, in execution order.
4. Call out anything non-obvious: workarounds, implicit dependencies, performance tradeoffs.
5. If it interacts with other files, mention them.

Be concise. Don't explain syntax — explain intent and decisions.
